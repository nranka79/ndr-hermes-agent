# Extract SharePoint/OneDrive Links from Gmail

Extract embedded sharing links from vendor email bodies (SharePoint, OneDrive, or any URL) when the user says "find the link in [person]'s email" or "can you give me the link from the email."

Use this when:
- A vendor/partner sends a sharing invite: "I shared a file with you" — the link lives in the HTML body, not as an attachment
- The user can't download via the link and needs the URL to try themselves or forward it
- The email is a SharePoint invite auto-generated by the sender's Microsoft 365

## Known vendors / domains that send SharePoint links

- **Godrej Venture / Godrej Industries** (godrejventure.com, godrejinds.co.in) — `godrejinds-my.sharepoint.com` personal sites
- Any organisation using Microsoft 365 with external sharing enabled

## Step-by-step extraction

### 1. Find the email

Search by sender domain and date:

```python
from tools.gws_auth import build_service
import base64

service = build_service('gmail', 'v1', service_name='google-draas')

results = service.users().messages().list(
    userId='me',
    q='from:harsimran.singh@godrejventure.com',
    maxResults=5
).execute()
```

### 2. Get the full message

Fetch with `format='full'` to get the complete MIME structure:

```python
msg = service.users().messages().get(
    userId='me', id=msg_id, format='full'
).execute()
```

### 3. Navigate to the HTML body

Standard Gmail MIME structure for a sharing invite:
```
payload.parts[0] = multipart/alternative
  └─ parts[0] = text/plain (short notification — no links)
  └─ parts[1] = text/html (full branded email with actual share link)
```

```python
parts = msg['payload'].get('parts', [])
alt_part = parts[0]  # multipart/alternative

for sp in alt_part.get('parts', []):
    if sp.get('mimeType') == 'text/html':
        html_data = sp['body']['data']
        html = base64.urlsafe_b64decode(html_data).decode('utf-8', errors='replace')
        break
```

### 4. Extract SharePoint/OneDrive links from HTML

SharePoint links follow the pattern:
`https://<tenant>-my.sharepoint.com/:u:/r/personal/<user>_<domain>/Documents/<file>?e=...`

```python
import re

urls = re.findall(r'href=[\'"]?([^\'" >]+)', html)
sharepoint_links = [u for u in urls if 'sharepoint.com' in u or 'onedrive.live.com' in u]

for link in set(sharepoint_links):
    clean = link.replace('&amp;', '&')  # decode HTML-encoded ampersands
    print(clean)
```

### 5. Present to user

Return the clean URL. The link encodes tenant, sender's personal site, filename, and a sharing token. The user may not be able to sign in if their domain has no Microsoft 365 account — the fix is asking the sender to attach directly.

## Email body patterns

- **Subject:** `<Name> shared "<Filename>" with you`
- **Body text/plain:** Brief notification — usually NO link here
- **Body text/html:** Full branded email with logo, file icon, and clickable share link
- **Attachments:** None — the file lives on SharePoint. Inline PNG parts are branding images, not the actual file
- **Sender:** The sharing person from their org domain (e.g. `harsimran.singh@godrejventure.com`)

## The follow-up email

The sender's second email (subject like `RE: 4.5 FAR Drawings`) typically explains the access situation. Common pattern from M365 orgs: "WeTransfer is not allowed in our organization, however I added the rights to the emails in the folder. Please check once now." This confirms it's a permission-granted share, not a public link — the user's email was added to the folder's access list.
