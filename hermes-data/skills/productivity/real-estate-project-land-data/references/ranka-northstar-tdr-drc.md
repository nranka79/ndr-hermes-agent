## Build workflow (HTML→PDF pack)
1. **NDR rule (HARD): get ALL details confirmed before building any HTML/PDF/pack.** Placeholders allowed for missing items (conversion OM copy, Aadhaar no, ₹100 e-stamp+notary+signatures — physical execution).
2. Toolchain (no weasyprint/pip in venv): chromium headless shell at `/opt/hermes/.playwright/chromium_headless_shell-1234/chrome-headless-shell-linux64/chrome-headless-shell` with `--headless --disable-gpu --no-sandbox --print-to-pdf=<out> --no-pdf-header-footer file://<html>`; merge with `qpdf --empty --pages a.pdf b.pdf -- out.pdf` (warnings about extraneous whitespace are non-fatal); JPEG→PDF via PIL `Image.convert('RGB').save(x,'PDF',resolution=150)` (gs fails on these JPEGs).
2b. **MANDATORY post-render check — every single time, including partial re-renders.** `--no-pdf-header-footer` is easy to drop when you re-render ONE file to fix a field (e.g. adding an OCI card) months after the original build. Without it chromium stamps `file:///tmp/.../x.html   1/3` at the bottom and a `9/24/26, 12:29 PM   <title>` line at the top of EVERY page — a leaked local temp path going to a government officer. Run `../scripts/check_pdf_chrome.sh <pdf...>` after every render; it must print 0 hits. If it fails, re-render with the flag and re-merge.
2c. **Rebuild the merged pack without re-rendering the scans.** The pack is front-matter (HTML→PDF) + scanned annexures. To fix front matter only: `qpdf --empty --pages current_pack.pdf <N>-<last> -- annexures.pdf` to lift the scan block out, then re-merge fixed front matter + annexures. Identify which pages are chromium-rendered by `pdftotext -layout -f K -l K pack.pdf - | head -1` — a page starting with a date/time line is chromium chrome, a blank or Kannada/garbled line is a scan.
3. Keep each write_file/patch under ~8K tokens — large writes stream-timeout.\n4. **Affidavit on stamp paper — bottom-third rule.** Indian notarised affidavits on ₹100-200 stamp paper must start at the bottom third of page 1 (the stamp / frank impression occupies the top ~66%). Add `@page :first { margin-top: 195mm; }` to the CSS block (side margins `18mm 16mm` inherited from `@page`). On A4 (297mm) this lands the first text at 198mm — exactly the bottom-third boundary. Verify with:\n   ```\n   pdftotext -bbox -f 1 -l 1 aff.pdf /dev/stdout\n   # Then compute min(yMin) / pageHeight — must be ≈67%\n   ```\n   The blank top space pushes the total page count up by 1 (e.g. 3→4 pages). The `:first` pseudo-class is supported by Chrome headless shell. Form IV / letters to authorities need NO stamp margin — only the Affidavit.
4. Upload: build_service('drive','v3') + MediaFileUpload; in-place update of pack files via files().update(fileId=...) to keep links stable.
5. Share & handoff to the colleague (NDR's pattern): grant editor via `svc.permissions().create(fileId=folder, body={'role':'writer','type':'user','emailAddress':colleague})`. ⚠️ **Drive API `expirationTime` (30-day access) fails on this account with "Expiration dates cannot be set on this item"** — grant without expiry and tell NDR it will NOT auto-revoke (offer a manual revoke later). Then create a Gmail DRAFT to the colleague (never send): pack Drive link → verify correctness → execute (e-stamp/notary/signature as GPA holder) → close pending items (conversion OM copy, Aadhaar no.) → confirm. Draft subject pattern: "<Project> — <Doc> Pack — Review & Action"; recipient only (no CC unless NDR says).
