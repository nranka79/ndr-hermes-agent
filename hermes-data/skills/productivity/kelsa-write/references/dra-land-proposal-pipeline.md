## Prerequisites for "Proposed" Stage

The entry stage requires completing a `data_entry: Report New Land Proposal` prerequisite with these required fields:
- `cf_date_of_proposal` (date)
- `cf_city` (dropdown)
- `cf_name` (text — this is the Proposal Brief)
- `cf_proposal_source` (dropdown, 91 options)
- `cf_proposal_source_details_notes` (text)
- `cf_land_size_uom` (dropdown)
- `cf_land_size_sqft` (number — required even if using Acres as UoM)
- `cf_offer_type` (dropdown)

## Automations

- Add followers on entry at "Proposed"
- Set assignee on entry (filter: cf_additional_team_member has value) at "Proposed"
- Add followers on entry (filter: Product Type = Warehousing) at "Proposed"

## Nuances & Shortcuts

- **Google Maps link in `cf_location_google_maplink`:** The field type is "attachment" but accepts a **plain URL string** (e.g. `https://maps.app.goo.gl/H19Ct6p6yHvwPK1z7`). Pass the URL as a string directly — no upload workflow needed. Verified on existing leads.
- **Required Sqft even with Acres UoM:** When using "Acres" as Land Size UoM, the `cf_land_size_sqft` field is still required. Calculate: acres × 43,560 = sqft.
- **Proposal Source is a person dropdown, not free-text:** Always search the pipeline for existing leads with the same source name first — the 91-option dropdown contains past brokers/agents. If the name isn't found, note it in `cf_proposal_source_details_notes` and let the user know it's not in the dropdown.
- **`cf_land_location` is free text:** Used for the location description (village, landmark, etc.). The dedicated `cf_village`, `cf_hobli`, `cf_taluk`, `cf_district`, `cf_sy_nos` fields exist but are often left empty — location details typically go in `cf_land_location` or Proposal Notes instead.
- **`cf_expected_jv_ratio_for_developer` is AUTO-CALCULATED (not settable via MCP):** This field computes as `100 - cf_expected_jv_ratio` (the Land Owner ratio). Setting it via `create_lead` or `update_lead` does NOT persist — MCP returns the computed value (e.g. `-37` if the field calc engine miscalculates from only one input being initially present). To have the correct Developer ratio shown, ensure `cf_expected_jv_ratio` (Land Owner) is set accurately; the Developer side will follow. If the display is wrong, the user may need to adjust it manually in the Kelsa UI — MCP cannot overwrite it.
