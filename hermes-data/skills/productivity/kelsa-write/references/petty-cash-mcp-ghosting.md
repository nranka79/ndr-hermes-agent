## Summary

Every `create_lead` call on Pipeline 555 via MCP returns "Record created successfully" with
a valid record ID, but the record **never persists**. Within seconds `get_lead()` returns
"not found or no access" and the pipeline's total record count stays unchanged.

## Symptoms

- `create_lead` returns `isError=false` with full field preview
- Record ID shown (e.g. `54045950`) 
- `get_lead(record_id)` → `"not found or no access"` within 5–15 seconds
- `search_leads` by name returns 0 results
- `get_draft_status(record_id)` → `"not found or no access"`
- Pipeline count stays at 70 (unchanged after dozens of test creates)

## What Was Tested

All combinations produced the same ghosting result:

| Variable | Values tested |
|----------|--------------|
| Request type | Advance, Reimbursement |
| Company ID format | Plain text ("DRA Realty Pvt Ltd."), `{"id": 2562316}`, `{"id": 2562315}`, `{"id": 1..59}`, `{"id": [large range]}` |
| Amount | 10, 50, 100, 5000 |
| User field (`cf_user1`) | Omitted, set to 41 (Nishant), set to 682 (Anbarasan) |
| Date | Omitted, set to "2026-07-25" |
| Attachment | Omitted (Advance), included via S3 upload+register (Reimbursement) |
| Pipeline access | `_connect_and_run` (standard), raw `httpx` JSON-RPC |
| Record name | Custom names, auto-generated by system |

## Root Cause (Diagnosis)

MCP-created records always show:

```
Created: 2026-07-25 16:47 by N/A
```

The **creator** field resolves to `"N/A"` (the MCP OAuth token has no user session
context — it authenticates at the account level, not the user level). The `cf_user1`
field (populated via `field_values` as `41`) correctly shows `User: Nishant Ranka`
in the record fields, but this is a DIFFERENT field from the record creator. The
async processor apparently requires a valid creator user and rejects records where
creator is `"N/A"` or `"system"`.

All 70 existing records in Pipeline 555 show `Created: ... by Bharat H` or another
named user — they were all created through the Kelsa web UI.

## What Doesn't Work

- Setting `cf_user1` in field_values (populates User field, NOT creator)
- Using any company ID format or value
- Including/excluding attachment
- Using Advance vs Reimbursement type
- Providing all required fields
- Using raw JSON-RPC vs wrapped `_connect_and_run`

## Workaround

**Cannot create records in Pipeline 555 via MCP.** Must use Kelsa web UI:
1. Navigate to https://app.kelsa.io/5/pipelines/555
2. Click "Add Cash request"
3. Select the company from the dropdown (resolves correctly in UI)
4. Fill in the fields with the prepared data
5. The S3 upload → register flow works through MCP (get_upload_url, curl, register_upload),
   so you can pre-upload attachments and provide the S3 URL for the UI
