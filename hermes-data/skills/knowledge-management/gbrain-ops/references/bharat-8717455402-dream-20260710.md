# Bharat sales1.blr — Dream 2026-07-10

## Context

Cron job targeted stale Telegram ID path `sales1.blr`. This path had a working
Postgres/Supabase gbrain config as of Jul 9 2026 (see
`bharat-sales1.blr-dream-20260709.md`), but the `.gbrain/config.json` was
cleaned up by Jul 10 — only the `audit/` subdirectory remained.

## First attempt — stale Telegram ID path, no `--dir`

Ran without `--dir` (no `/data/hermes/users/sales1.blr/brain/` exists):

```sh
HOME=/data/hermes/users/sales1.blr \
  /data/hermes/home/.local/bin/bun run /opt/gbrain/src/cli.ts dream --json
```

**Result**: `brain_dir` resolved to `/data/hermes/users/psingh/brain` —
**wrong user** (Prakash Singh, not Bharat). gbrain fell through to an
incorrect default when it couldn't find a config at the expected path.

**Diagnosis**: The `brain_dir` field in dream JSON is the strongest red flag
for wrong-user resolution. Always check it against the expected user.

## Second attempt — DRAAS account path with GBRAIN_HOME

```sh
GBRAIN_HOME=/data/hermes/users/sales1.blr/.gbrain-writable \
  /data/hermes/home/.local/bin/bun run /opt/gbrain/src/cli.ts dream --json \
  --dir /data/hermes/users/sales1.blr/brain
```

## Key learnings

1. **Postgres config at stale Telegram ID path can be cleaned up between
   runs.** The config.json that existed on Jul 9 was gone by Jul 10. This is
   not a transient failure — the Telegram ID path is an artifact and its
   config is unreliable.

2. **Missing config + no --dir → wrong user brain_dir.** Without a config
   at the stale path and without `--dir` pointing to a specific brain,
   gbrain resolved to an unrelated user's brain (`psingh`). Always check
   `brain_dir` in dream output.

3. **GBRAIN_HOME + direct brain dir works when safe.directory is set.** The
   DRAAS account path `sales1.blr` is fully functional via `GBRAIN_HOME`
   pointing to `.gbrain-writable` and `--dir` pointing to the root-owned
   brain. No brain-copy needed.
