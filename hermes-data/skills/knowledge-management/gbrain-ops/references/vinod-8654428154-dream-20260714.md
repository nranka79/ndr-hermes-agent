## Key observations

- **The cron target is the foot-gun, not gbrain**: The agent's emergency fallback to the default scaffold is the documented behavior when both `HOME` and `--dir` point at a non-existent user. gbrain doesn't crash — it just runs against phantom content. The detection requires checking the JSON's `phases` for the three fingerprint markers above.
- **`gbrain dream` does NOT require `--dir` in gbrain 0.42.x** — the cron's literal `--dir /data/hermes/users/[REDACTED-TID]/brain` is doubly wrong: the flag is optional in current versions, AND the path is stale. The cron's intent was probably correct (specify a brain path) but the path was never updated when Vinod was migrated from Telegram ID to DRAAS account.
- **Embed error is structural**: `zeroentropyai:zembed-1` is the default embedding model baked into gbrain's scaffold. It will keep failing until `ZEROENTROPY_API_KEY` is added to the cron env, OR the embedding model is switched to one with available credentials (e.g. `openrouter:openai/text-embedding-3-small` after exporting `OPENROUTER_API_KEY` from the user's `.openrouter_key`).
- **`propose_takes` 7 ANTHROPIC_API_KEY warnings** — same pattern as every Vinod run. The LLM extractor needs `ANTHROPIC_API_KEY` exported into the subprocess env, not just present in `/opt/hermes/.env`. The key is in `/opt/hermes/.env` for Hermes itself, but `bun run` doesn't inherit it into the subprocess. See the gbrain-ops "LLM extraction/proposal phases may warn (harmless)" pitfall.
- **No rate limit hit**: The instruction's "if rate limit is hit, note it and skip gracefully" was not triggered. Embed failed on missing credential, not 429. This matches Runs 4/6/8/9 for Vinod — consistent platform limitation, not transient.
- **Status `ok` is misleading** — the cycle technically succeeded against the scaffold, but no user content was processed. A more accurate signal would be `partial` or a new `default_scaffold` status. The skill's "default-scaffold fingerprint" pattern is the current way to detect this scenario.
- **Cron fix recommendation**: Update the cron's `uid` field from `[REDACTED-TID]` (Telegram ID) to `vkdas` (DRAAS account). Then the agent will resolve to `/data/hermes/users/vkdas/.gbrain/` (the real config) and `/data/hermes/users/vkdas/brain` (the real brain) — or `vkdas/brain-copy` (the hermes-owned working copy with git history). See the Per-User Isolation table in the gbrain-ops SKILL.md for the authoritative mapping.
